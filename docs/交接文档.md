## 二、为什么网页放 GitHub Pages、数据库还在 WorkBuddy

- **WorkBuddy 平台挡微信**：从微信里打开 WorkBuddy 托管的任何网页，都会返回「当前应用不支持在微信内打开」，第一期网址现在也一样。WorkBuddy 里没有开关可以改。新建的应用还默认只认带 `?sharecode=` 的链接，改不成公开。所以网页不能再放 WorkBuddy。
- **WorkBuddy 数据库不挡微信，但挑来源**：它拒绝别的网址发来的请求（请求头 Origin 不是它自己的域名，就返回 403），但接受 Origin 为 null 的请求。
- **解决办法：沙盒外壳**。6 个原始页面放在发布目录的 `app/` 下；外层同名的 6 个 html 只是外壳（`pages/shell.js`），把 `app/` 里的页面装进 `sandbox` 的 iframe。框里发出的请求 Origin 是 null，数据库才肯收。
- 框里不能用浏览器存储，`cloud.js` 开头的代码改由外壳代存，后台登录、打分页「记住是谁」都照常。地址栏和标题会跟着框里的页面变。
- **只要数据库还在 WorkBuddy，网页放在任何别的域名都必须用外壳版**，不能直接放原始 html，否则所有读写都会 403。外壳版放在别的服务器上时，还要给 `app/fonts/` 加 `Access-Control-Allow-Origin: *` 响应头，否则数字字体会退回系统字体。GitHub Pages 默认就带这个头。

## 三、改代码与发布

- `main` 分支是源码。`gh-pages` 分支是发布产物，由脚本生成，不要手改。
- 生成发布文件：`bash pages/build.sh <输出目录>`。输出目录里就是要上线的全部内容：6 个外壳 html、`shell.js`、`.nojekyll`、`app/`。
- 发布到 GitHub Pages：
  1. 用 `git worktree add <目录> gh-pages` 取出发布分支；
  2. 在该目录运行上面的脚本，然后提交、`git push`；
  3. 等一两分钟生效。
- 发布后逐个比对线上和本地文件（curl 下载后算 md5）。
- 改了 `cloud.js` / `theme.css` / `deco.js`，要把 6 个 html 里的 `?v=` 统一加 1（现在是 12），否则现场设备会用缓存的旧代码。
- 数据库连接和后台口令指纹在 `cloud.js` 顶部。后台口令 `baiyan2026`，代码里只存了 SHA-256 指纹。
